### Phase 1 — LLM upgrade (original spec was Anthropic/Claude)
User had no budget for Anthropic API keys → provider switched to **Groq's free tier**
(30 RPM / ~1,000–14,400 RPD per model, no credit card). Architecture unchanged from the original plan:

```
raw query
   │
   ▼
PlanningAgent ── LLM call #1 (forced tool call → guaranteed JSON:
   │             intent / location_name / time_window / agents_needed / why)
   ▼
OceanStateAgent ── deterministic seeded simulation (UNTOUCHED)
   │              + LLM call #2 → reasoning_note ("report to a colleague")
   ▼
HazardAgent ── fixed numeric thresholds (UNTOUCHED)
   │          + LLM call #3 → reasoning_note explaining the verdict
   ▼
SynthesisAgent ── LLM call #4 → ONE coherent user-facing answer
   │              + flags cross-agent contradictions in `conflicts`
   ▼
OrchestratorResponse (same dataclass contract + new fields)
```

Key design rules enforced in prompts:
- LLMs reason **on top of** the deterministic data layer; they may never invent numbers.
- Structured outputs use **forced tool calling** (`tool_choice` pinned), not string parsing.
- Every LLM step produces a normal `AgentTrace` entry with real `duration_ms`.
- **Graceful degradation:** missing key / API failure after retry-once → falls back to the
  original rule-based path, trace shows `[mode=rules]` / `[llm_unavailable]`. Demo never crashes.

## 6. Phase 2.1 — Response quality fixes (found during user's live /docs testing)

User ran a real query through the Swagger UI and pasted the full JSON back.
Verdict: data/verdict/provenance all correct, but **two LLM-output flaws** were spotted:

| # | Flaw in the response | Root cause | Fix |
|---|---|---|---|
| 1 | `ocean_state.reasoning_note` ended mid-sentence (*"...gusting to"*) | `gpt-oss` is a reasoning model — hidden thinking tokens consume the same completion budget, so some calls silently truncated at low `max_tokens` | (a) `llm_client.complete()` now treats `finish_reason == "length"` as a failure → triggers the retry-once path; (b) note budgets raised 220→600 tokens in both agents |
| 2 | Final answer cited *"a tide of 2.05 m"* as if measured — tide is SIMULATED | Synthesis prompt never saw `field_sources`, so it blended simulated numbers into prose undistinguished | SynthesisAgent now injects the per-field provenance table into its prompt + new rule 5: *"If you cite a simulated field's number, explicitly say that value is estimated/simulated, not measured."* |

Diagnostic used to confirm root cause 1: direct API call showed
`finish_reason: stop, completion_tokens: 153` on a short prompt — proving truncation only
occurs when reasoning runs long, i.e. stochastic, hence retry is the right handler.

## 8. Phase 3 — LangGraph orchestration (2026-08-24)

**Goal executed:** replace the hardcoded sequential dispatch in
`Orchestrator.handle_query()` with a real **LangGraph StateGraph**, per the
target topology in `orca_final_architecture.py` (planning → conditional
routing → specialist chain → synthesis), while keeping every existing agent,
the Groq client, live-data logic, and the `OrchestratorResponse` contract
byte-compatible — `main.py` and `test_run.py` unchanged.

### Graph topology now running

```
START -> planning --[intent==safety_check]--> ocean_state -> hazard -> synthesis -> END
              \---[otherwise]-----------> unsupported -------------------------------^
```

| Concept from architecture file | Implementation |
|---|---|
| Shared graph state (`ORCAState` TypedDict) | `ORCAGraphState` carrying raw query, plan, context, agent results, response |
| Add-only merge channel (`Annotated[..., operator.add]`) | `traces` channel — every node appends its `AgentTrace`; ready for parallel fan-out later |
| Conditional edges / orchestrator-selected routing | `_route_after_plan()` on the Planning Agent's parsed intent |
| Separate synthesis + response nodes | Single `synthesis` node (SynthesisAgent already emits the final user-facing answer) |

Planning logic (`_plan`, forced tool schema, rule fallbacks) untouched. |

### Orchestrator rewired

- Planning schema v2: intents now `{safety_check, pfz_lookup, route_plan,
  geofence_check, hazard_alerts, unknown}`; rule-based keyword router extended
  to match.
- `INTENT_DEFAULT_AGENTS` maps each intent to its warranted specialist set;
  planner's `agents_needed` intersects with it; explicit device GPS or
  destination ALWAYS forces the Geospatial Agent.
- `QueryContext` grew `language`, optional `device_gps`, optional
  `destination`; `OrchestratorResponse` grew `language`, `pfz`, `geofence`,
  `route` (main.py `/query` accepts them; JSON-safe serialization verified).
- **Fan-out lesson learned:** native per-agent graph branches double-fired the
  synthesis/response join when branches ended in different supersteps (hazard
  finishes ~3 s after ocean). Tried list-routing AND the Send API — both
  re-fire. Solution: single `specialists` dispatch node running selected
  agents concurrently via `ThreadPoolExecutor` (ocean→hazard chained inside
  one worker; PFZ and Geospatial truly parallel alongside). Exactly one
  synthesis pass, real wall-clock parallelism preserved. Documented in code.
- Per-specialist failures are caught, logged, and skipped — a dead PFZ agent
  no longer kills a safety query.
